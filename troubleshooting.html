故障排查

本页汇总运行 OpenRLHF（人类反馈强化学习框架） 最常遇到的问题。

升级后出现 “argparse: unrecognized arguments”（无法识别参数）

OpenRLHF 0.10.2 将每个 CLI（命令行接口）参数移到点号分隔的配置部分前缀下。旧平铺名称（--pretrain、--zero_stage、--vllm_num_engines、--learning_rate 等）无法解析，argparse 会报错。请将启动脚本迁到新接口；Flag migration (0.9.x / early 0.10 → 0.10.2)（位于 常用 CLI（命令行接口）选项）有完整旧 → 新参数表，examples/scripts/ 下全部文件均已迁移。

GPU（图形处理器）设备索引 / DeepSpeed（分布式训练框架）初始化错误

遇到 GPU 设备映射问题（常见于 DeepSpeed 初始化），尝试：

export RAY_EXPERIMENTAL_NOSET_CUDA_VISIBLE_DEVICES=1  # NVIDIA
export RAY_EXPERIMENTAL_NOSET_ROCR_VISIBLE_DEVICES=1  # AMD

然后重启 Ray（分布式计算框架）并重新运行作业。

Out-of-memory（OOM，内存不足）

常见缓解措施（大致按优先顺序）：

  • 减小批次大小（--train.micro_batch_size、--rollout.micro_batch_size）。

  • 降低 vLLM（推理引擎）显存比例（--vllm.gpu_memory_utilization）。

  • 禁用 colocation（同置，移除 --train.colocate_*）。

  • 启用节省显存的选项（--ds.adam_offload、--actor.gradient_checkpointing_enable / --model.gradient_checkpointing_enable，以及更高 --ds.zero_stage）。

详细调优见 性能调优 和 Hybrid Engine（混合引擎）。

Muon（矩阵参数优化器）与 DeepSpeed 兼容性

--optim muon / --actor.optim muon 不兼容于 --ds.adam_offload，DS 的 Muon 将优化器状态留在 GPU。若需 adam-offload 节省显存，请改回 Adam。

DeepSpeed 0.18.x 中，--muon.ns_steps 和 --muon.nesterov / --muon.no_nesterov 是 占位参数：DS 的 muon_update() 内核硬编码 ns_steps=5 和 Nesterov（前瞻动量） True。修改只产生运行时警告，无实际效果。这些选项保留用于兼容未来版本。

Muon 要求 DeepSpeed ≥ 0.18.2。旧版 DS 未注册 MuonWithAuxAdam 类型时会在初始化报错，请升级或改回 --optim adam。

vLLM 挂起 / NCCL（GPU 集合通信库）问题

vLLM 权重同步时挂起，或遇到 NCCL 问题：

  • 尝试 --vllm.enforce_eager（禁用 CUDA（NVIDIA 的并行计算平台） graph（CUDA 图））。

  • 多 GPU 设置优先使用 --vllm.sync_backend nccl。

更多排查技巧见 Hybrid Engine（混合引擎）。

Ray 运行环境问题

Worker（工作进程）缺少依赖时，通过 runtime env（运行环境）让 Ray 安装：

--runtime-env-json='{"setup_commands": ["pip install openrlhf[vllm]"]}'

用 py-spy（Python 采样分析工具）调试（容器内）

用 py-spy 快速查看正在运行的 OpenRLHF Python 进程在 CPU（中央处理器）上做什么。

  1. 在容器内安装：

pip install py-spy

  1. 查找训练 PID（进程 ID，常用关键词：openrlhf / ray / vllm）：

ps auxww | rg "openrlhf|ray::|train_ppo_ray|train_sft|train_rm|train_dpo|vllm"

  1. 连接并检查：

py-spy top --pid <PID>
py-spy record --pid <PID> --duration 30 -o profile.svg

若 Docker（容器平台）中连接失败，请启用 ptrace（进程跟踪）启动容器：

docker run ... --cap-add=SYS_PTRACE --security-opt seccomp=unconfined ...
