RL（强化学习）训练指南

本页是 OpenRLHF（开源强化学习训练框架）中 RL 训练的完整参考。所有算法和执行模式都通过同一智能体执行流水线运行。

监督学习方法（SFT（监督微调）、RM（奖励模型）、DPO（直接偏好优化））见 监督与偏好训练（SFT（监督微调）/RM（奖励模型）/DPO（直接偏好优化））；概念模型见 设计范式：基于 Agent（智能体）的执行；通用 CLI（命令行接口）标志见 常用 CLI（命令行接口）选项；同步与异步流水线见 Hybrid Engine（混合引擎） 和 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）。

Overview

OpenRLHF 的每次 RL 运行都组合了三项相互独立的选择：

维度

选项

设置方式

执行模式

单轮（默认）| 多轮

默认 / --reward.remote_url | --train.agent_func_path

RL 算法

PPO（近端策略优化）/ REINFORCE++（改进策略梯度方法）/ REINFORCE++-baseline（采用奖励基线的 REINFORCE++）/ RLOO（留一法奖励基线方法）/ GRPO（组相对策略优化）/ Dr. GRPO（修正 GRPO 偏差的变体）

--algo.advantage.estimator

流水线

同步（Hybrid Engine（混合引擎））| 异步（可选 partial rollout（可中断并恢复的部分采样生成））

Hybrid Engine（混合引擎） | 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）

这些维度相互独立：任何算法都能在任意模式和流水线中运行，因为每次 rollout（策略采样生成）都产生 token（文本词元）级轨迹，由损失层以相同方式使用。

Quick Launch (Ray + vLLM)

文档中的默认 RL 示例是 Qwen3-4B-Thinking（通义千问推理模型）使用 REINFORCE++-baseline，在数学任务上进行 RLVR（基于可验证奖励的强化学习）训练。完整启动命令见 Hybrid Engine（混合引擎），下面是仅含关键标志的最小版本：

# launch the master node of ray in a container
ray start --head --node-ip-address 0.0.0.0 --num-gpus 8

ray job submit --address="http://127.0.0.1:8265" \
   --runtime-env-json='{"working_dir": "/openrlhf"}' \
   -- python3 -m openrlhf.cli.train_ppo_ray \
   --actor.model_name_or_path Qwen/Qwen3-4B-Thinking-2507 \
   --reward.remote_url examples/python/math_reward_func.py \
   --data.prompt_dataset zhuzilin/dapo-math-17k \
   --data.input_key prompt \
   --data.label_key label \
   --data.apply_chat_template \
   --ds.packing_samples \
   \
   --ref.num_nodes 1 \
   --ref.num_gpus_per_node 4 \
   --actor.num_nodes 1 \
   --actor.num_gpus_per_node 4 \
   --vllm.num_engines 2 \
   --vllm.tensor_parallel_size 2 \
   --train.colocate_all \
   --vllm.gpu_memory_utilization 0.7 \
   --vllm.enable_sleep \
   --ds.enable_sleep \
   --vllm.sync_backend nccl \
   --vllm.enforce_eager \
   \
   --algo.advantage.estimator reinforce_baseline \
   --algo.kl.use_loss \
   --algo.kl.estimator k2 \
   --algo.kl.init_coef 1e-5 \
   --actor.entropy_coef 0.0 \
   --algo.advantage.is_correction_enable \
   --algo.advantage.is_correction_type icepop \
   \
   --rollout.batch_size 128 \
   --rollout.n_samples_per_prompt 8 \
   --train.batch_size 1024 \
   --algo.dynamic_filtering_enable \
   --algo.dynamic_filtering_range 0.0 1.0 \
   --train.dynamic_batch_enable \
   --data.max_len 74240 \
   --rollout.max_new_tokens 64000 \
   \
   --ds.zero_stage 3 \
   --ds.param_dtype bf16 \
   --actor.gradient_checkpointing_enable \
   --actor.adam.lr 5e-7 \
   --ckpt.output_dir ./exp/Qwen3-4B-Thinking

说明

  • 此处使用 Hybrid Engine；详细配置说明见 Hybrid Engine（混合引擎）。

  • Ray（分布式计算框架）+ vLLM（大模型推理引擎）目前不支持 LoRA（低秩适配）。

  • 自动将环境部署到 Ray worker（工作进程）：--runtime-env-json='{"setup_commands": ["pip install openrlhf[vllm]"]}'。

  • GPU（图形处理器）索引问题：export RAY_EXPERIMENTAL_NOSET_CUDA_VISIBLE_DEVICES=1（NVIDIA（英伟达））或 RAY_EXPERIMENTAL_NOSET_ROCR_VISIBLE_DEVICES=1（AMD）。

Execution Modes

执行模式决定如何采集经验。请根据任务结构选择。

Single-Turn Mode (default)

一个提示词 → 一个回复 → 一个奖励，覆盖绝大多数 RLHF（基于人类反馈的强化学习）场景。奖励来源为以下之一：

  1. 已训练的奖励模型 — 设置 --reward.model_name_or_path。

  2. 远程 HTTP（超文本传输协议）RM 服务器 — 设置 --reward.remote_url http://host:5000/get_reward。

  3. 本地 Python（编程语言）奖励函数 — 设置 --reward.remote_url /path/to/reward_func.py。这可实现面向代码、数学、格式和多目标奖励等任务的 Reinforced Fine-Tuning（强化微调，RFT）。

远程奖励模型服务器。在 HTTP 端点后部署大型 RM：

python -m openrlhf.cli.serve_rm \
   --reward.model_name_or_path OpenRLHF/Llama-3-8b-rm-700k \
   --port 5000 \
   --ds.param_dtype bf16 \
   --ds.attn_implementation flash_attention_2 \
   --reward.normalize_enable \
   --data.max_len 8192 \
   --batch_size 16

# then in the trainer:
python3 -m openrlhf.cli.train_ppo_ray \
   --reward.remote_url http://localhost:5000/get_reward \
   ...

自定义奖励函数（RFT）。将 Python 文件路径传给 --reward.remote_url，OpenRLHF 会在运行时导入并调用。通过 --data.label_key answer 传入标准答案字段：

# reward_func.py
import torch

def reward_func(queries, prompts, labels):
    """
    Args:
        queries: list[str] — full text (prompt + response) per sample
        prompts: list[str] — original prompts
        labels:  list[str] — ground-truth labels (from --data.label_key)

    Returns:
        dict with:
            rewards:    Tensor — used in advantage calculation
            scores:     Tensor — used by --algo.dynamic_filtering_enable (typically in [0, 1])
            extra_logs: dict   — values logged to Wandb / TensorBoard
    """
    batch_size = len(queries)
    reward = torch.zeros(batch_size)
    for i, (q, label) in enumerate(zip(queries, labels)):
        reward[i] = 1.0 if my_check(q, label) else 0.0
    return {
        "rewards": reward,
        "scores": reward,
        "extra_logs": {"accuracy": reward.mean().item()},
    }

端到端示例：train_ppo_with_reward_fn.sh。

提示

典型 RFT 场景：代码（运行单元测试）、数学（验证最终答案）、JSON（结构化数据格式）格式校验（正则检查）、多目标奖励（组合信号）。

Multi-Turn Mode

对于推理链、带反馈的编程、游戏和工具使用等多步交互，请实现多轮智能体，通过 --train.agent_func_path 传入。每个样本成为一个 episode（完整交互回合）：

  1. 使用初始提示词和标签重置环境。

  2. 模型生成一个动作。

  3. 环境返回反馈、可选奖励以及 done。

  4. 重复，直到 done=True。

OpenRLHF 将这些内容封装为同一 token-in-token-out（词元输入/词元输出）轨迹供损失层使用，因此任何 RL 算法都能直接运行。

实现智能体。继承 AgentInstanceBase，并可选地将其封装到 MultiTurnAgentExecutor：

# agent_func.py
from typing import Any, Dict
import torch
from openrlhf.utils.agent import AgentInstanceBase, MultiTurnAgentExecutor


class AgentInstance(AgentInstanceBase):
    def __init__(self, *args, **kwargs):
        self.step_idx = 0

    async def reset(self, states: dict, **kwargs) -> dict:
        # states: {"observation": <prompt>, "label": <ground truth>, ...}
        self.step_idx = 0
        return {"observation": states["observation"]}

    async def step(self, states: dict, **kwargs) -> Dict[str, Any]:
        # states: observation_text / action_text / label / sampling_params / ...
        self.step_idx += 1
        done = self.step_idx >= 3
        reward = torch.tensor(1.0) if done else torch.tensor(0.0)

        feedback = (
            "\n\nHuman: [CORRECT]\n</s>"
            if done
            else "\n\nHuman: [INCORRECT]\nPlease analyze and try again.\n</s>\n\nAssistant: "
        )

        return {
            "rewards": reward,                 # used for advantage
            "scores": reward,                  # used for dynamic filtering
            "environment_feedback": feedback,  # appended to next-turn context
            "done": done,
            "sampling_params": states.get("sampling_params"),
            "extra_logs": {"step": self.step_idx},
        }


class AgentExecutor(MultiTurnAgentExecutor):
    def __init__(self):
        super().__init__(AgentInstance)

返回值约定：

  • reset(states) → {"observation": str}.

  • step(states) → 字典，包含 rewards（Tensor，张量）、scores（Tensor）、environment_feedback（str）、done（bool）。可选项：sampling_params（每步的 vLLM 参数）、environment_images（用于 VLM（视觉语言模型）智能体）、extra_logs（指标字典）。

要完整自定义 token 级控制，直接继承 AgentExecutorBase 并实现 execute()，但请遵循 token-in-token-out 原则，保持采样与训练一致。

启动：

python3 -m openrlhf.cli.train_ppo_ray \
   --actor.model_name_or_path Qwen/Qwen3-4B-Thinking-2507 \
   --train.agent_func_path /path/to/agent_func.py \
   ...

要提高吞吐量，可添加 --train.async_enable，也可选添加 --train.partial_rollout_enable；见 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）。

兼容 OpenAI（人工智能服务平台）的 Agent Server（智能体服务器）。智能体需要 OpenAI 风格聊天 API（应用编程接口） 时（如接入已有工具使用框架），examples/python/agent_func_openai_server_executor.py 将本地 vLLM 封装为 /v1/chat/completions 服务器，同时仍采集 token 级追踪用于 RL 训练：

  • 标准端点：/v1/chat/completions、/v1/models、/tokenize。

  • 自动采集每个会话的 token ID 和对数概率。

  • Delta-tokenization（增量分词）在多轮调用间复用前缀 token。

  • 覆盖 run_agent()，接入自己的多轮工作流。

python3 -m openrlhf.cli.train_ppo_ray \
   --train.agent_func_path examples/python/agent_func_openai_server_executor.py \
   ...

RL Algorithms

算法决定如何根据采集的轨迹更新策略，通过 --algo.advantage.estimator 选择。算法的差异包括是否使用 critic（价值模型）、如何设置奖励基线，以及如何归一化优势值。所有算法均适用于每种执行模式和流水线。

算法

--algo.advantage.estimator

核心思想

最适合

PPO

gae （默认）

使用完整 critic 的 GAE（广义优势估计）；裁剪代理目标

通用 RLHF，稳定训练

REINFORCE++

reinforce

无需 critic；PPO 裁剪、KL（Kullback–Leibler 散度）惩罚和奖励归一化

内存占用低于 PPO

REINFORCE++-baseline

reinforce_baseline

以平均奖励为基线（无 critic，不进行逐提示词标准差归一化）

RLVR/推理 — 对奖励尺度稳健

RLOO

rloo

留一法基线 + PPO 裁剪 + 逐 token KL

每个提示词生成多个样本的训练

GRPO

group_norm

按组均值/标准差归一化 + KL 损失项

基于批次的推理训练

Dr. GRPO

dr_grpo

不进行局部 /std 归一化的 GRPO

逐组标准差归一化影响效果时

算法专属要求：

  • rloo / reinforce_baseline / group_norm 需要 --rollout.n_samples_per_prompt > 1。

  • group_norm（GRPO）通常搭配 --algo.kl.use_loss 和 --algo.kl.estimator k3。

Optimizer: Adam or Muon (per entity)

PPO 有两个独立优化的模型：actor（策略模型）和 critic。0.10.2 支持按实体选择优化器：

标志

含义

--actor.optim {adam, muon}

Actor 优化器（默认 adam）。

--critic.optim {adam, muon}

Critic 优化器（默认 adam）。

--actor.muon.lr / --actor.muon.momentum

actor 的 Muon（矩阵权重优化器）二维权重组设置。

--actor.adam.lr

当 --actor.optim adam 时的 Adam（自适应矩估计优化器）LR（学习率）；当 --actor.optim muon 时，也用于 Muon 辅助 Adam 子组（嵌入/LM head（语言模型输出头）/一维参数）。

--actor.adam.betas / --actor.adam.eps / --actor.adam.weight_decay

actor 的 AdamW（带解耦权重衰减的 Adam）超参数。

--actor.lr_scheduler / --actor.lr_warmup_ratio / --actor.min_lr_ratio / --actor.max_norm

各实体独立的调度器和梯度裁剪。critic 端将 actor 替换为 critic；二者完全独立。

典型的“actor-Muon、critic-Adam”组合（0.10.2 中可用一行设置）：

--actor.optim muon \
--actor.muon.lr 0.02 --actor.muon.momentum 0.95 \
--actor.adam.lr 5e-7 \
--critic.optim adam \
--critic.adam.lr 9e-6

Muon 需要 DeepSpeed（分布式训练优化框架）≥ 0.18.2，且不兼容 --ds.adam_offload。详细注意事项见 常用 CLI（命令行接口）选项（ns_steps / Nesterov（前瞻动量）占位设置、权重衰减语义）。

Tuning

以下标志是围绕所选算法的调优参数。实际使用中，多数用户主要调整 KL 控制和长度惩罚参数。

Loss & clipping

标志

含义

--actor.eps_clip

PPO 裁剪范围（默认 0.2）。

--actor.eps_clip_low_high <low> <high>

非对称裁剪边界；设置后覆盖 --actor.eps_clip。

--actor.dual_clip <c>

Dual-clip PPO（双重裁剪 PPO）上界（典型值 c=3）；防止负优势值上的策略更新过大。

--critic.value_clip

Critic 价值裁剪（默认 0.5）。

--actor.policy_loss_type {ppo, gspo}

切换标准 PPO 与 GSPO（组序列策略优化）风格的损失聚合。

Advantage / GAE

标志

含义

--algo.advantage.gamma

折扣因子（默认 1.0，将轨迹视为一个完整 episode，不进行折扣）。

--algo.advantage.lambd

GAE 的 λ（默认 1.0）；降低 λ，以增加偏差换取降低方差。

--algo.advantage.no_std_norm

保留均值中心化，但不再除以优势值标准差。

KL control

当前策略与参考策略之间的 KL 散度，可以作为奖励惩罚，也可以作为独立损失项：

标志

含义

--algo.kl.init_coef

初始 KL 系数（默认 0.01）。设为 0 可完全禁用参考模型。

--algo.kl.target / --algo.kl.horizon

自适应 KL 控制器：设置 --algo.kl.target 后，系数会在 --algo.kl.horizon 步内向该目标自适应调整。

--algo.kl.use_loss

将 KL 加为独立损失项（GRPO 风格），而非奖励惩罚。

--algo.kl.estimator {k1, k2, k3}

KL 估计器：k1 用于标准 PPO 惩罚；作为损失时 k2 ≈ k1；k3 用于 GRPO 损失。

推荐搭配（搭配不同时，训练器会警告）：

  • KL 作为奖励惩罚（无 --algo.kl.use_loss）：--algo.kl.estimator k1 是唯一合理选择。典型配置：标准 PPO 或 REINFORCE++ 使用 --algo.kl.init_coef 0.01 --algo.kl.estimator k1。

  • KL 作为损失项（--algo.kl.use_loss）：使用 --algo.kl.estimator k2 或 k3（k1 不是有效损失）。典型配置：GRPO 使用 --algo.kl.use_loss --algo.kl.estimator k3；Hybrid Engine（混合引擎） 中默认 RLVR 实践方案使用 --algo.kl.use_loss --algo.kl.estimator k2 --algo.kl.init_coef 1e-5，搭配 REINFORCE++-baseline。

Entropy

  • --actor.entropy_coef：熵正则化系数。None 禁用；0 仅记录熵，不将其作为损失。

Reward shaping

标志

含义

--reward.normalize_enable

使用在线滚动均值/标准差归一化原始奖励。

--reward.clip_range <low> <high>

优势计算前，对原始奖励进行截限（默认 -10 10）。

--reward.overlong_buffer_len <L>

DAPO（解耦裁剪与动态采样策略优化）风格的软长度限制：惩罚长度超过 max_new_tokens - L 的回复。

--reward.overlong_penalty_factor

超长惩罚的乘法幅度（默认 1.0）。

--reward.stop_properly_penalty_coef <c>

对满足 finish_reason='length' 的样本使用 ProRL（强化学习训练方案）风格的截断惩罚。c >= 0 时将奖励乘以 c ∈ [0, 1]；c < 0 时覆盖奖励（如 -0.5）。

Off-policy correction (TIS / ICEPOP / Seq-Mask-TIS)

vLLM 使用与训练器不同的内核，有时精度也不同，因此相同 token 序列在 rollout 与训练中可能产生略有差异的对数概率。OpenRLHF 可以通过 importance-sampling correction（重要性采样修正，IS）补偿。

通过 --algo.advantage.is_correction_enable 启用，并选择策略：

策略

标志

行为

TIS（截断重要性采样） （默认）

--algo.advantage.is_correction_type tis

在 token 级将 IS 比率截限到 [low, high]。

ICEPOP（区间外系数置零的采样修正）

--algo.advantage.is_correction_type icepop

Token 级过滤：将 [low, high] 之外的系数置零，不进行截限。

Seq-Mask-TIS（序列掩码截断重要性采样）

--algo.advantage.is_correction_type seq-mask-tis

序列级几何平均掩码。

阈值：--algo.advantage.is_correction_threshold <low> <high>（默认 0.5 5.0）。背景：off-policy RL training。

ICEPOP 等价于硬掩码：

# ICEPOP: zero-out coefficients outside the interval
vllm_is = exp(old_log_probs - rollout_log_probs)
mask = (vllm_is >= low) & (vllm_is <= high)
vllm_is = vllm_is * mask

提示

异步加 partial rollout 与 ICEPOP 自然适配，因为在途样本会混用旧、新权重。见 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）。

Dynamic sampling (DAPO)

推理任务中，为每个提示词生成多个回复，仅使用其中一部分训练：

标志

含义

--rollout.n_samples_per_prompt

每个提示词的回复数量（过滤/RLOO/GRPO/REINFORCE++-baseline 时必须 > 1）。

--algo.dynamic_filtering_enable

使用奖励/智能体函数返回的 scores，启用 DAPO 风格过滤。

--algo.dynamic_filtering_range <low> <high>

保留的奖励范围，例如 0.0 1.0。丢弃范围外样本。

--rollout.vllm_generate_batch_size

vLLM 生成批次大小；可超过 --rollout.batch_size 以进行过采样。需要 --train.async_enable，在大于 --rollout.batch_size 时。

--train.dynamic_batch_enable

按 token 预算而非样本数量组成微批次，对变长序列能实现更好的打包。搭配 --train.max_tokens_per_gpu 和 --rollout.max_tokens_per_gpu。

经验性大小规则：train.batch_size = rollout.batch_size * rollout.n_samples_per_prompt。启用 --algo.dynamic_filtering_enable 时，如果大量样本被过滤，有效批次可能缩小；通过 --rollout.vllm_generate_batch_size 保留过采样余量（仅异步）。

端到端 DAPO 实践方案：train_dapo_ray_hybrid_engine.sh。

Sampling & misc

  • --rollout.top_p / --rollout.temperature：rollout 期间的 vLLM 采样参数。

  • --critic.freezing_steps：critic 预热时，在前 N 次更新中冻结 actor。

  • --critic.save_value_network：同时保存 critic 检查点（仅 PPO）。

  • --train.full_determinism_enable：逐位可复现的行为（更慢；vLLM v1 与固定种子路径）。

Vision-Language Model (VLM) RLHF

自 OpenRLHF 0.10 起，VLM（如 Qwen3.5）可以使用图像输入进行端到端训练。框架通过 HuggingFace（模型与工具平台）配置中的 vision_config 字段自动识别 VLM，使用 AutoModelForImageTextToText 加载，通过 AutoProcessor 正确插入图像 token，再将图像传给 vLLM，进行多模态生成。

其意义在于：以往 VLM RLHF 配置需要自定义数据加载器和专用推理路径。OpenRLHF 对 VLM 复用与纯文本模型相同的智能体执行流水线、相同的 RL 算法及相同的 Hybrid Engine，只需添加少量标志。

VLM 专属标志：

标志

含义

--data.image_key

数据集 JSON 中保存图像路径/URL 的键（默认 images）。

--data.max_images_per_prompt

每个提示词允许 vLLM 使用的最大图像数量（0 = 纯文本；默认 0）。

--actor.freeze_visual_encoder

冻结视觉编码器，只训练语言模型权重并将其同步到 vLLM，节省显存和权重同步时间。

数据集格式（JSONL（每行一个 JSON 对象的格式））：

{
    "prompt": [
        {"role": "user", "content": [
            {"type": "image"},
            {"type": "text", "text": "Find x."}
        ]}
    ],
    "images": ["/path/to/image.png"],
    "label": "3"
}

端到端示例，见 train_vlm_math_hybrid_engine.sh：

python3 -m openrlhf.cli.train_ppo_ray \
   --actor.model_name_or_path Qwen/Qwen3.5-2B \
   --reward.remote_url examples/python/math_reward_func.py \
   --data.prompt_dataset hiyouga/geometry3k \
   --data.input_key prompt \
   --data.label_key label \
   --data.image_key images \
   --data.max_images_per_prompt 1 \
   --actor.freeze_visual_encoder \
   --data.max_len 4096 \
   --rollout.max_new_tokens 2048 \
   --algo.advantage.estimator reinforce_baseline \
   --train.colocate_all \
   --vllm.gpu_memory_utilization 0.7 \
   --data.apply_chat_template \
   --ds.attn_implementation eager \
   --ds.param_dtype bf16 \
   ...

说明

  • 已测试：Qwen3.5（混合线性注意力与完整注意力）。

  • 自动识别，尚未测试：采用 ForConditionalGeneration 架构的 VLM（Gemma4、LLaVA、InternVL 等）。

  • 对包含线性注意力层的模型使用 --ds.attn_implementation eager；flash attention（高效注意力计算实现）可能不支持这些层的打包序列。

  • VLM 训练不支持 --ds.packing_samples（打包会合并批次维度，破坏图像与 token 对齐），也不支持 PPO critic（请使用无需 critic 的 --algo.advantage.estimator，例如 reinforce_baseline / rloo / group_norm）。

  • 支持多轮 VLM RLHF，见 vlm_multiturn_agent.py。

Logging & evaluation

  • --logger.wandb.key {token} / --logger.wandb.project / --logger.wandb.group / --logger.wandb.run_name：Wandb（实验跟踪工具）日志。

  • --logger.tensorboard_dir {logdir}：TensorBoard（训练可视化工具）日志。

  • --logger.logging_steps：每 N 个训练步骤记录一次日志。

  • --eval.steps / --eval.dataset：在留出数据集上定期评估。

  • --train.num_episodes：运行的 RL episode 总数（一个 episode = 对 rollout.batch_size 个提示词完整执行一轮 rollout）。

训练指标包括策略损失、KL、熵、奖励/优势统计、生成长度、梯度范数以及各阶段实际耗时。保存与恢复机制见 Checkpoint（检查点）保存与恢复，调优见 性能调优。
