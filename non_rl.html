监督与偏好训练（SFT（监督微调）/RM（奖励模型）/DPO（直接偏好优化））

本页介绍 OpenRLHF（人类反馈强化学习框架） 的非 RL（强化学习） trainer（训练器）：监督微调、奖励模型训练与直接偏好优化。它们是 RL 训练的标准准备步骤（SFT → RM → PPO（近端策略优化）），亦可独立使用。

RL 训练（PPO、REINFORCE++（策略梯度算法）、GRPO（组相对策略优化）、RLOO（留一法策略梯度）、自定义奖励、多轮 agent（智能体）、VLM（视觉语言模型））参见 RL（强化学习）训练指南。共享 CLI（命令行接口）选项见 常用 CLI（命令行接口）选项。

说明

三种 trainer（训练器）都接受 0.10.2 hierarchical CLI（分层命令行接口）。单模型配置在 --model.* 下；优化器在 --adam.* / --muon.* 下（由 --optim 选择）；调度器和梯度裁剪保持平铺（--lr_scheduler、--lr_warmup_ratio、--min_lr_ratio、--max_norm）。--pretrain 或 --learning_rate 等旧平铺参数已无法解析，参见 Flag migration (0.9.x / early 0.10 → 0.10.2)。

说明

早期 OpenRLHF 提供 KTO（基于 Kahneman–Tversky 理论的偏好优化）、PRM（过程奖励模型）、Knowledge Distillation（知识蒸馏）以及基于 batch_inference 的迭代工作流（拒绝采样、迭代 DPO、条件 SFT）。这些模块已从上游代码库移除，需要时请固定使用较早版本。

  • Reward Model (RM) Training

  • Direct Preference Optimization (DPO)

Supervised Fine-tuning (SFT)

deepspeed --module openrlhf.cli.train_sft \
   --model.model_name_or_path meta-llama/Meta-Llama-3-8B \
   --data.dataset Open-Orca/OpenOrca \
   --data.input_key question \
   --data.output_key response \
   --data.input_template $'User: {}\nAssistant: ' \
   --data.max_samples 500000 \
   --data.max_len 2048 \
   --ds.packing_samples \
   --train.batch_size 256 \
   --train.micro_batch_size 8 \
   --train.max_epochs 1 \
   --adam.lr 5e-6 \
   --ds.zero_stage 2 \
   --ds.param_dtype bf16 \
   --ds.attn_implementation flash_attention_2 \
   --model.gradient_checkpointing_enable \
   --ckpt.output_dir ./checkpoint/llama3-8b-sft \
   --ckpt.save_steps -1 \
   --logger.logging_steps 1 \
   --eval.steps -1 \
   --logger.wandb.key {wandb_token}

SFT（监督微调）专属参数：

  • --data.input_key / --data.output_key：数据集 JSON 中 prompt（提示词）和目标响应的键。

  • --data.apply_chat_template：使用 tokenizer（分词器）的 chat template（对话模板）渲染对话（对话数据集需配合 --data.input_key）。

  • --data.tokenizer_chat_template：覆盖 tokenizer 默认对话模板。

  • --data.input_template：不使用对话模板时的自定义 Python 格式字符串（如 $'User: {}\nAssistant: '）。

  • --data.multiturn：使用 紧凑 多轮数据集格式训练（损失作用于所有 assistant（助手）轮次）。要求 --data.apply_chat_template。

  • --model.pretrain_mode_enable：切换为预训练式损失（在整个序列上进行下一 token（词元）预测），适用于继续预训练。

  • --ds.packing_samples：每序列打包多个样本，配合 FlashAttention（高效注意力实现）实现约 2–3 倍加速。

  • --ds.ring_attn_size / --ds.ring_attn_head_stride：启用 RingAttention（环形注意力）处理长上下文（参见 Sequence Parallelism（序列并行，RingAttention））。

  • --model.aux_loss_coef：MoE（混合专家）均衡损失系数（MoE 模型设置 > 0）。

说明

OpenRLHF SFT / DPO / PPO / RM trainer 均支持 --ds.packing_samples（packing reference）。

Reward Model (RM) Training

deepspeed --module openrlhf.cli.train_rm \
   --model.model_name_or_path OpenRLHF/Llama-3-8b-sft-mixture \
   --data.dataset OpenRLHF/preference_dataset_mixture2_and_safe_pku \
   --data.apply_chat_template \
   --data.chosen_key chosen \
   --data.rejected_key rejected \
   --data.max_len 8192 \
   --ds.packing_samples \
   --train.batch_size 256 \
   --train.micro_batch_size 4 \
   --train.max_epochs 1 \
   --adam.lr 9e-6 \
   --ds.zero_stage 3 \
   --ds.param_dtype bf16 \
   --ds.attn_implementation flash_attention_2 \
   --model.gradient_checkpointing_enable \
   --ckpt.output_dir ./checkpoint/llama3-8b-rm \
   --ckpt.save_steps -1 \
   --logger.logging_steps 1 \
   --eval.steps -1 \
   --logger.wandb.key {wandb_token}

RM（奖励模型）专属参数：

  • --data.chosen_key / --data.rejected_key：数据集 JSON 中优选与 rejected（非优选）响应的键。

  • --ds.value_head_prefix：score head（评分头）名称前缀（默认 score）。设为 score 后，可用 AutoModelForSequenceClassification 加载训练好的模型。

  • --model.loss_type：RM 损失类型（默认 sigmoid）。

  • --model.margin_loss_enable：使用基于 margin（间隔）的损失（逐样本间隔），代替普通 Bradley–Terry（成对偏好概率模型）；数据集需有 margin 字段。

  • --model.compute_fp32_loss_enable：用 FP32（32 位浮点）计算 RM 损失以保证数值稳定性（bf16（16 位脑浮点）损失不稳定时有用）。

  • --ds.packing_samples：打包 RM 样本以加速。

使用 --ds.value_head_prefix score 加载训练好的 RM：

reward_model = AutoModelForSequenceClassification.from_pretrained(
    reward_model_path,
    num_labels=1,
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2",
    use_cache=False,
)
# inputs: left-padded token IDs
reward = reward_model.model(*inputs).last_hidden_state
reward = reward_model.score(reward)[:, -1]

Direct Preference Optimization (DPO)

deepspeed --module openrlhf.cli.train_dpo \
   --model.model_name_or_path OpenRLHF/Llama-3-8b-sft-mixture \
   --data.dataset OpenRLHF/preference_dataset_mixture2_and_safe_pku \
   --data.apply_chat_template \
   --data.chosen_key chosen \
   --data.rejected_key rejected \
   --data.max_len 8192 \
   --ds.packing_samples \
   --train.batch_size 256 \
   --train.micro_batch_size 1 \
   --train.max_epochs 1 \
   --adam.lr 5e-7 \
   --model.beta 0.1 \
   --ds.zero_stage 3 \
   --ds.param_dtype bf16 \
   --ds.attn_implementation flash_attention_2 \
   --model.gradient_checkpointing_enable \
   --ckpt.output_dir ./checkpoint/llama3-8b-dpo \
   --ckpt.save_steps -1 \
   --logger.logging_steps 1 \
   --eval.steps -1 \
   --logger.wandb.key {wandb_token}

DPO（直接偏好优化）专属参数：

  • --data.chosen_key / --data.rejected_key：数据集 JSON 中偏好对的键。

  • --model.beta：DPO 温度。β 越大，越接近参考策略；β 越小，偏离越激进。典型范围：0.1–0.5。

  • --model.ipo_enable：切换为 IPO（恒等偏好优化）损失（Identity Preference Optimization）。

  • --model.label_smoothing：启用 cDPO（保守 DPO），label smoothing（标签平滑）取值在 (0, 0.5) 内。

  • --model.nll_loss_coef：对 chosen response（被偏好的响应）添加 NLL（负对数似然）正则项（依据 Llama 3.1 技术报告），通常可提高稳定性。

  • --ref.offload：在两次前向传播之间将参考模型卸载到 CPU（中央处理器），节省 GPU（图形处理器）显存。

  • --min_lr_ratio：最小学习率占初始 LR（学习率）的比例（用于 cosine_with_min_lr 调度器，默认 0.1）。

  • --ds.packing_samples：打包 DPO 样本。

Optimizer: Adam or Muon

三种 trainer 提供 相同的优化器切换选项。通过 --optim 选择优化器，再在匹配部分配置（另一部分保留默认值，会被忽略）：

切换选项

生效部分

忽略部分

--optim adam （默认）

--adam.lr / --adam.betas / --adam.eps / --adam.weight_decay

--muon.*

--optim muon

--muon.lr / --muon.momentum + --adam.lr / --adam.betas / --adam.eps / --adam.weight_decay（用于 embedding（嵌入）、LM head（语言模型输出头）和一维参数的 aux-Adam（辅助 Adam）子组复用每个 --adam.* 选项；学习率调度器驱动两个参数组）

无：Muon 下 --adam.* 始终生效。

Muon（矩阵参数优化器）示例（SFT）：Llama-3-8B 运行中 actor（策略模型）侧的 DS-Muon：

deepspeed --module openrlhf.cli.train_sft \
   --model.model_name_or_path meta-llama/Meta-Llama-3-8B \
   --data.dataset Open-Orca/OpenOrca \
   --data.input_key question --data.output_key response \
   --data.max_len 2048 --ds.packing_samples \
   --train.batch_size 256 --train.micro_batch_size 8 \
   --train.max_epochs 1 \
   --optim muon \
   --muon.lr 0.02 \
   --muon.momentum 0.95 \
   --adam.lr 5e-6 \
   --adam.weight_decay 0.0 \
   --lr_scheduler cosine_with_min_lr \
   --lr_warmup_ratio 0.03 \
   --min_lr_ratio 0.1 \
   --max_norm 1.0 \
   --ds.zero_stage 2 --ds.param_dtype bf16 \
   --ds.attn_implementation flash_attention_2 \
   --model.gradient_checkpointing_enable \
   --ckpt.output_dir ./checkpoint/llama3-8b-sft-muon

说明

Muon 要求与注意事项

  • 要求 DeepSpeed（分布式训练框架）≥ 0.18.2；OpenRLHF 会代为构建 DS Muon 配置。

  • --ds.adam_offload 与 Muon 不兼容，DS 的 Muon 将优化器状态留在 GPU。保持 --ds.adam_offload 禁用，只要使用 --optim muon。

  • --muon.ns_steps 和 --muon.nesterov 是 占位参数：DeepSpeed 0.18.x 硬编码 ns_steps=5 和 Nesterov（前瞻动量） True，位于 muon_update() 内。修改它们只产生运行时警告，不改变行为。当前暴露这些选项是为兼容未来 DS 版本。

  • Muon 仅更新二维隐藏权重矩阵。embedding、LM head 和一维参数（LayerNorm（层归一化）/偏置）由 aux-Adam 子组以 --adam.lr 优化。

  • 共享 weight decay（权重衰减）。DeepSpeed 0.18.x 将同一个 weight_decay 写入两组；OpenRLHF 从 --adam.weight_decay 读取。没有独立 --muon.weight_decay 参数。

  • Muon 下偏置/LayerNorm 不获豁免。纯 Adam 路径不对偏置和 LayerNorm 施加权重衰减；Muon 下 DS 拒绝参数组字典，对每个参数应用相同 weight_decay。

LoRA / QLoRA

上述三个 trainer 均支持 LoRA（低秩适配）和 QLoRA（量化低秩适配），设置 --ds.lora.rank > 0（QLoRA 还需 --ds.load_in_4bit）。启用 LoRA 时仅保存 adapter（适配器）权重，使用 openrlhf.cli.lora_combiner 与基座模型合并（见 常用 CLI（命令行接口）选项）。

示例：Mixtral 的 SFT + LoRA：

deepspeed --module openrlhf.cli.train_sft \
   --model.model_name_or_path mistralai/Mixtral-8x7B-v0.1 \
   --data.dataset Open-Orca/OpenOrca \
   --data.max_len 2048 --ds.packing_samples \
   --train.batch_size 128 --train.micro_batch_size 1 \
   --train.max_epochs 1 \
   --adam.lr 5e-6 \
   --ds.zero_stage 3 --ds.param_dtype bf16 \
   --ds.attn_implementation flash_attention_2 \
   --model.gradient_checkpointing_enable \
   --ds.lora.rank 64 --ds.lora.alpha 64 \
   --ckpt.output_dir ./checkpoint/mixtral-sft-lora

说明

Ray（分布式计算框架）+ vLLM（推理引擎）（PPO）目前 不支持 LoRA，仅 SFT / RM / DPO 可用。
