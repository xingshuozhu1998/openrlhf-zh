异步训练与 Partial Rollout（可中断并恢复的部分采样生成）

同步 RLHF（基于人类反馈的强化学习，默认）每次执行一个阶段：rollout（策略采样生成）结束后训练，再开始下一次 rollout。异步训练通过并发运行 rollout 与训练，消除这一流水线空闲。Partial rollout 更进一步，将权重同步与生成本身重叠。

这些功能以吞吐量为目标，以少量 on-policy（同策略）程度的损失，换取显著更高的 GPU（图形处理器）利用率。请在同步模式下验证收敛后使用。

底层架构见 架构基础：Ray（分布式计算框架）+ vLLM（大模型推理引擎）分布式架构；替代的同步流水线见 Hybrid Engine（混合引擎）。

How it works

同步流水线（默认）：

┌────────────┐    ┌──────────┐    ┌────────────┐    ┌──────────┐
│  rollout   │───▶│  train   │───▶│  rollout   │───▶│  train   │
└────────────┘    └──────────┘    └────────────┘    └──────────┘
                       (one phase at a time, GPUs alternate roles)

异步流水线（ --train.async_enable ）：

┌────────────┐  ┌────────────┐  ┌────────────┐  ┌────────────┐
│  rollout   │─▶│  rollout   │─▶│  rollout   │─▶│  rollout   │
└─────┬──────┘  └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
      │ (queue)       │               │               │
      ▼               ▼               ▼               ▼
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  train   │───▶│  train   │───▶│  train   │───▶│  train   │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
(rollout and train run concurrently; bounded queue between them)

异步 + Partial Rollout（ --train.partial_rollout_enable ）：vLLM（大模型推理引擎）从不完全停止。训练器推送新权重时，vLLM 暂停在途请求，切换权重后恢复。因此，同一样本可包含旧、新权重生成的 token（文本词元），以 off-policy（异策略）噪声换取完整重叠。

参数

标志

含义

--train.async_enable

启用异步流水线。rollout 与训练通过有界队列重叠运行。

--train.async_queue_size

rollout 与训练之间的队列深度（默认 1）。更大的值提高吞吐量，但增加 off-policy 滞后。

--train.partial_rollout_enable

通过 vLLM 暂停/恢复进行权重同步，使生成与权重广播重叠。需要 --train.async_enable。

--rollout.vllm_generate_batch_size

vLLM 生成批次大小；设得大于 --rollout.batch_size 可启用过采样。需要 --train.async_enable，在大于 --rollout.batch_size 时。

兼容性说明：

  • --train.async_enable 不兼容 --vllm.enable_sleep。训练器会断言检查；请移除 --vllm.enable_sleep，再添加 --train.async_enable。

  • --train.colocate_all 可与 --train.async_enable 组合，但异步模式下仅将 DeepSpeed（分布式训练优化框架） 模型（Actor（策略模型）/Ref（参考模型）/Critic（价值模型）/Reward（奖励模型））同置于共享 GPU；vLLM 保留自己的 GPU 组，以持续生成。

  • 若想在不使用异步的情况下最大化 GPU 利用率，请优先选择同步 Hybrid Engine（混合引擎）（--train.colocate_all --vllm.enable_sleep --ds.enable_sleep）。

Launch recipe (async + partial rollout)

这是上游 train_reinforce_baseline_ray_agent_async.sh，展开为一次 ray job submit 调用：

export VLLM_USE_V1=1

ray job submit --address="http://127.0.0.1:8265" \
   --runtime-env-json='{"working_dir": "/openrlhf"}' \
   -- python3 -m openrlhf.cli.train_ppo_ray \
   --actor.model_name_or_path Qwen/Qwen3-4B-Thinking-2507 \
   --train.agent_func_path examples/python/agent_func.py \
   --data.prompt_dataset zhuzilin/dapo-math-17k \
   --data.input_key prompt \
   --data.label_key label \
   --data.apply_chat_template \
   --ds.packing_samples \
   \
   --train.async_enable \
   --train.partial_rollout_enable \
   \
   --ref.num_nodes 1 \
   --ref.num_gpus_per_node 4 \
   --actor.num_nodes 1 \
   --actor.num_gpus_per_node 4 \
   --vllm.num_engines 2 \
   --vllm.tensor_parallel_size 2 \
   --vllm.gpu_memory_utilization 0.95 \
   --train.colocate_all \
   --ds.enable_sleep \
   --vllm.sync_backend nccl \
   --vllm.enforce_eager \
   \
   --rollout.batch_size 128 \
   --rollout.n_samples_per_prompt 8 \
   --train.batch_size 1024 \
   --algo.dynamic_filtering_enable \
   --algo.dynamic_filtering_range 0.0 1.0 \
   --train.dynamic_batch_enable \
   --train.max_tokens_per_gpu 16192 \
   --rollout.max_tokens_per_gpu 32768 \
   --train.micro_batch_size 1 \
   --rollout.micro_batch_size 8 \
   --data.max_len 74240 \
   --rollout.max_new_tokens 64000 \
   --data.max_samples 128000 \
   --train.max_epochs 1 \
   --train.num_episodes 1 \
   \
   --algo.advantage.estimator reinforce_baseline \
   --actor.adam.lr 5e-7 \
   --actor.entropy_coef 0.0 \
   --algo.kl.init_coef 1e-5 \
   --algo.kl.use_loss \
   --algo.kl.estimator k2 \
   --algo.advantage.is_correction_enable \
   --algo.advantage.is_correction_type icepop \
   \
   --ds.zero_stage 3 \
   --actor.gradient_checkpointing_enable \
   --ds.ring_attn_size 2 \
   --ds.ring_attn_head_stride 2 \
   --ds.param_dtype bf16 \
   \
   --ckpt.output_dir ./exp/Qwen3-4B-Thinking \
   --ckpt.path ./exp/Qwen3-4B-Thinking/ckpt \
   --ckpt.save_hf \
   --ckpt.max_num 3 \
   --ckpt.save_steps 10 \
   --logger.logging_steps 1 \
   --eval.steps -1

Tuning guide

  • 从 ``–train.async_queue_size 1`` 开始，这是最小的 off-policy 滞后（约 1 步）。仅在 rollout 成为训练瓶颈时增大。

  • 将 partial rollout 与 off-policy 修正搭配。由于在途样本混用旧、新权重，请启用 --algo.advantage.is_correction_enable（推理工作负载通常使用 --algo.advantage.is_correction_type icepop）。

  • 先在同步模式验证收敛。异步加 partial rollout 可能掩盖其他参数导致的收敛退化。

  • vLLM 生成利用不足时，增大 ``–rollout.vllm_generate_batch_size``——异步模式允许生成端超额采样，不阻塞 trainer。

When not to use async

  • 对 off-policy 噪声敏感的任务（小模型、短 rollout、稀疏奖励）。

  • 尚未验证同步模式收敛性的情况。

  • 同步开销本已较低的单节点小规模运行。

这些情况请使用 Hybrid Engine（混合引擎），兼顾吞吐量与稳定性。

警告

异步训练与 partial rollout 吞吐量最高，但可能影响敏感任务的收敛性。切换前，务必验证同步模式的收敛性。
