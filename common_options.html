常用 CLI（命令行接口）选项

OpenRLHF（人类反馈强化学习框架） 0.10.2 为每个 CLI 选项使用带点号的分组前缀，体现所属组件：--ds.* 对应 DeepSpeed（分布式深度学习优化库），--vllm.* 对应 vLLM（大模型推理引擎），--rollout.* 对应生成参数，--data.* / --train.* / --eval.* / --ckpt.* / --logger.* / --algo.* 对应流水线阶段；PPO（近端策略优化）使用按实体划分的 --actor.* / --critic.* / --ref.* / --reward.*，单模型 trainer（训练器）（SFT（监督微调）/RM（奖励模型）/DPO（直接偏好优化））使用 --model.*。早期扁平别名已移除，所有启动脚本必须使用新名称。

本页是集中选项参考。Trainer 专用参数见 监督与偏好训练（SFT（监督微调）/RM（奖励模型）/DPO（直接偏好优化）） 与 RL（强化学习）训练指南；端到端启动脚本位于 examples/scripts。

Section map

前缀

所属组件

包含内容

--ds.*

DeepSpeed 与模型加载

zero_stage、param_dtype、adam_offload、tensor_parallel_size、zpg、overlap_comm、grad_accum_dtype、deepcompile、enable_sleep、ring_attn_size、ring_attn_head_stride、use_universal_ckpt、attn_implementation、experts_implementation、use_liger_kernel、load_in_4bit、lora.{rank, alpha, dropout, target_modules}、packing_samples、value_head_prefix（RM / PPO 奖励头）。

--vllm.*

vLLM 生成引擎

num_engines, tensor_parallel_size, gpu_memory_utilization, sync_backend, sync_with_ray, enforce_eager, enable_prefix_caching, enable_sleep.

--rollout.*

Rollout（采样生成）/采样

batch_size, micro_batch_size, n_samples_per_prompt, temperature, top_p, max_new_tokens, max_tokens_per_gpu, vllm_generate_batch_size.

--data.*

数据集与分词

prompt_dataset（PPO）或 dataset（SFT/RM/DPO）、数据划分 / 采样概率、键映射、模板处理、max_len、max_samples、image_key、max_images_per_prompt、multiturn、dataloader_num_workers。

--train.*

训练编排

batch_size, micro_batch_size, max_tokens_per_gpu, max_epochs, num_episodes, seed, full_determinism_enable, async_enable / async_queue_size / partial_rollout_enable, dynamic_batch_enable, enable_ema / ema_beta, agent_func_path, colocate_actor_ref / colocate_critic_reward / colocate_all.

--eval.*

评估

dataset, split, steps, temperature, n_samples_per_prompt.

--ckpt.*

Checkpoint（检查点）保存与恢复

output_dir, path, save_steps, save_hf, disable_ds, max_num, max_mem, load_enable, best_metric_key.

--logger.*

日志

logging_steps, tensorboard_dir, wandb.{key, org, group, project, run_name}.

--algo.*

RL（强化学习）算法（仅 PPO）

advantage.{estimator, gamma, lambd, no_std_norm, is_correction_enable, is_correction_type, is_correction_threshold}, kl.{init_coef, target, horizon, estimator, use_loss}, dynamic_filtering_enable, dynamic_filtering_range.

--actor.* / --critic.* / --ref.* / --reward.*

各角色的模型配置（PPO）

model_name_or_path、num_nodes、num_gpus_per_node、gradient_checkpointing_enable、freeze_visual_encoder（actor（策略模型）），optim / adam.* / muon.*，lr_scheduler / lr_warmup_ratio / min_lr_ratio / max_norm，以及各角色专用损失 / 裁剪 / 卸载参数。引擎级模型加载（attn_implementation、lora.*、packing_samples、load_in_4bit、use_liger_kernel）位于 --ds.* 下，由各角色共享。

--model.*

单模型损失/加载配置（SFT / RM / DPO）

model_name_or_path、gradient_checkpointing_enable、aux_loss_coef、beta（DPO）、ipo_enable、label_smoothing、nll_loss_coef、loss_type / compute_fp32_loss_enable / margin_loss_enable（RM）、pretrain_mode_enable（SFT）。引擎级模型加载与 LoRA（低秩适配）位于 --ds.* 下。

（扁平）

启动器与特殊选项

--optim、--lr_scheduler、--lr_warmup_ratio、--min_lr_ratio、--max_norm（SFT/RM/DPO 使用扁平选项，PPO 按实体划分）、--local_rank（DeepSpeed 注入）、--use_ms（ModelScope（模型生态平台））。

说明

命名约定：名称尚未表达判断含义的布尔开关带显式 _enable 后缀，例如 --reward.normalize_enable、--ckpt.load_enable、--train.async_enable、--train.dynamic_batch_enable、--algo.dynamic_filtering_enable、--algo.advantage.is_correction_enable。已使用动词形式的选项（freeze_*、save_*、enforce_*、colocate_*、use_*、*_offload）不加后缀。

DeepSpeed

标志

含义

--ds.zero_stage

DeepSpeed ZeRO（零冗余优化器）阶段（0 / 1 / 2 / 3）。大模型使用 3。

--ds.tensor_parallel_size

DeepSpeed 张量并行（AutoTP（自动张量并行））规模——仅适用于 --ds.zero_stage 0/1/2。

--ds.adam_offload

将 Adam（优化器）状态卸载至 CPU（中央处理器），节省 GPU（图形处理器）显存，但增加单步耗时。不兼容 Muon（优化器）——DS 的 Muon 实现将优化器状态保存在 GPU。

--ds.param_dtype

参数 dtype（数据类型）：bf16（默认）或 fp16。

--ds.zpg

ZeRO++ 最大分区大小（默认 1）。

--ds.overlap_comm

重叠反向传播与梯度归约（更大的 bucket（通信桶）预算，需要更多显存）。

--ds.grad_accum_dtype

Adam 梯度累积 dtype。

--ds.deepcompile

启用 DeepCompile 图编译（PyTorch（深度学习框架）2.0+）。

--ds.enable_sleep

DeepSpeed 休眠模式——在训练步骤间释放 DeepSpeed 显存（Hybrid Engine（混合引擎）需配合 --vllm.enable_sleep + --train.colocate_all）。

--ds.ring_attn_size / --ds.ring_attn_head_stride

RingAttention（环形注意力）的序列并行组 / 注意力头步幅（参见 Sequence Parallelism（序列并行，RingAttention））。

--ds.use_universal_ckpt

使用 DeepSpeed Universal Checkpoint（通用检查点）格式（不依赖 ZeRO 阶段或 world size（进程总数））。

--ds.attn_implementation

Attention（注意力）后端：eager / flash_attention_2 / flash_attention_3 / kernels-community/vllm-flash-attn3。由 trainer 加载的所有模型共享（actor / critic（价值评估模型）/ reward（奖励模型）/ reference（参考模型），或单个 SFT/RM/DPO 模型）。

--ds.experts_implementation

传递给 transformers.from_pretrained 的 MoE（混合专家模型）专家计算策略。None（默认）让 transformers（预训练模型库）自动选择（支持时选 grouped_mm，否则选 eager）；显式选项为 eager / batched_mm / grouped_mm / deepgemm。

--ds.use_liger_kernel

为融合算子启用 Liger Kernel。

--ds.load_in_4bit

以 4-bit 加载基础模型（QLoRA（量化低秩适配），配合 --ds.lora.*）。

--ds.lora.{rank, alpha, dropout, target_modules}

LoRA / QLoRA 配置（设置 --ds.lora.rank > 0 启用）。仅支持 SFT / RM / DPO；Ray（分布式执行框架）+ vLLM PPO 不支持 LoRA。

--ds.packing_samples

在每个序列打包多个样本（Flash-Attention（高效注意力计算）路径），显著提高吞吐量。

--ds.value_head_prefix

序列回归模型的评分头名称前缀（RM 训练、PPO 奖励模型加载器、serve_rm）。默认 score。

vLLM

标志

含义

--vllm.num_engines

vLLM 引擎数量（0 完全禁用 vLLM，适用于非 RL trainer）。

--vllm.tensor_parallel_size

每个 vLLM 引擎的张量并行规模。

--vllm.gpu_memory_utilization

KV-cache（键值缓存）比例。8×A100-80G 上从 0.5 开始，稳定后提高。

--vllm.sync_backend

DeepSpeed → vLLM 权重同步后端（多 GPU 上推荐 nccl）。

--vllm.sync_with_ray

使用 Ray group（进程组）而非直接使用 NCCL（多 GPU 集合通信库）同步权重。

--vllm.enforce_eager

禁用 vLLM 中的 CUDA（NVIDIA 的并行计算平台） graph（GPU 计算图）（避免某些挂起情况，并减少显存占用）。

--vllm.enable_prefix_caching

启用 vLLM 前缀缓存（适合配合 --rollout.n_samples_per_prompt > 1）。

--vllm.enable_sleep

vLLM 休眠模式——在 rollout 之间释放大部分 vLLM 显存。仅适用于 Hybrid Engine；不兼容 --train.async_enable。

Rollout / generation

标志

含义

--rollout.batch_size

每个 rollout 步骤的 prompt（提示）批次大小（经验收集批次）。

--rollout.micro_batch_size

对已生成样本前向计算时，每 GPU 的 micro-batch（微批次）大小（例如重新计算对数概率）。

--rollout.n_samples_per_prompt

每个 prompt 的 completion（完整回答）数。RLOO（留一法策略梯度）/REINFORCE++-baseline（带基线的 REINFORCE++）/GRPO（组相对策略优化）/动态过滤要求为 > 1。

--rollout.temperature / --rollout.top_p

Rollout 中的 vLLM 采样参数。

--rollout.max_new_tokens

每个样本最多生成的 token（词元）数。None → 动态设为 max_len - prompt_len。

--rollout.max_tokens_per_gpu

Rollout 端前向计算的每 GPU token 预算（配合 --train.dynamic_batch_enable）。

--rollout.vllm_generate_batch_size

vLLM 生成批次。大于 --rollout.batch_size 时，需要 --train.async_enable（超额采样的额外批次缓存于异步队列）。

Data

各 trainer 共享。注意，prompt 输入选项不同：PPO 使用 --data.prompt_dataset（值为数据集路径，由旧 --data.prompt 重命名），SFT / RM / DPO 使用 --data.dataset。

标志

含义

--data.prompt_dataset （PPO） / --data.dataset （SFT/RM/DPO）

HuggingFace（模型生态平台）数据集名称或路径。混合数据集时用逗号分隔。

--data.prompt_probs （PPO） / --data.dataset_probs （SFT/RM/DPO）

混合多个数据集时的采样概率（例如 0.1,0.4,0.5）。

--data.prompt_split （PPO） / --data.dataset_split （SFT/RM/DPO）

HF 数据划分名称（默认 train）。

--data.input_key / --data.output_key / --data.label_key

Prompt、SFT 目标与 RL 标准答案标签的 JSON（数据交换格式）键。

--data.prompt_key / --data.chosen_key / --data.rejected_key

偏好数据集的键（RM / DPO）。

--data.image_key

VLM（视觉语言模型）图像路径 / URL 键（默认 images）。

--data.apply_chat_template

应用 tokenizer（分词器）的聊天模板。

--data.tokenizer_chat_template

覆盖 tokenizer 的默认聊天模板。

--data.input_template

不使用聊天模板时的纯文本格式字符串（例如 $'User: {}\nAssistant: '）。

--data.max_len

最大总序列长度（prompt + response）。

--data.max_samples

训练样本数上限。

--data.dataloader_num_workers

DataLoader（数据加载器）worker 数（默认 0；Ray 训练须确保每个 actor 分配足够 CPU）。

--data.disable_fast_tokenizer

强制 use_fast=False，应用于 AutoTokenizer。

--data.multiturn

（SFT）在紧凑多轮聊天数据上训练（损失应用于所有 assistant（助手）轮次）。需要 --data.apply_chat_template。

--data.max_images_per_prompt

（PPO VLM）vLLM 每个 prompt 的最大图片数（0 = 仅文本）。

Training

标志

含义

--train.batch_size / --train.micro_batch_size

全局与每 GPU 训练批次大小。

--train.max_tokens_per_gpu

训练时每 GPU token 预算（配合 --train.dynamic_batch_enable）。

--train.max_epochs

每次 rollout 的 PPO 优化 epoch（轮次）数（SFT / RM / DPO 则为遍历数据集的轮次）。

--train.num_episodes （PPO）

RL episode（训练回合）总数（一个 episode = 完整遍历一次 prompt 集）。

--train.seed

全局随机种子（默认 42）。

--train.full_determinism_enable

逐位可复现行为（较慢；vLLM v1 + 固定随机种子路径）。

--train.dynamic_batch_enable

按 token 预算而非样本数量组成 micro-batch，能更好地打包变长序列。配合 --train.max_tokens_per_gpu / --rollout.max_tokens_per_gpu。

--train.async_enable / --train.async_queue_size / --train.partial_rollout_enable

异步流水线控制（参见 异步训练与 Partial Rollout（可中断并恢复的部分采样生成））。

--train.enable_ema / --train.ema_beta

跟踪 actor 的 EMA（指数移动平均）副本（参见 Checkpoint（检查点）保存与恢复）。

--train.agent_func_path

多轮 agent（智能体）Python 文件。配置多轮执行器（参见 RL（强化学习）训练指南）。

--train.colocate_actor_ref / --train.colocate_critic_reward / --train.colocate_all

Ray / vLLM 资源放置的角色共置配置（参见 Hybrid Engine（混合引擎））。

Evaluation

  • --eval.dataset：评估数据集路径（PPO 配合 --data.prompt_dataset；仅限使用奖励函数的运行）。

  • --eval.split：评估数据划分（不同 trainer 默认值不同）。

  • --eval.steps：每 N 个训练步评估一次（-1 禁用）。

  • --eval.temperature / --eval.n_samples_per_prompt （PPO）：评估 rollout 的采样参数。

Checkpoint（检查点）保存与恢复

标志

含义

--ckpt.output_dir

最终 HuggingFace 格式模型保存路径（训练结束始终写入）。

--ckpt.path

可恢复的 DeepSpeed 格式 checkpoint 目录。

--ckpt.save_steps

两次 checkpoint 保存之间的步数（-1 = 从不保存）。

--ckpt.save_hf

每个 checkpoint 同时导出 HF 格式模型。

--ckpt.disable_ds

跳过 DeepSpeed checkpoint，训练进度无法恢复。

--ckpt.max_num / --ckpt.max_mem

保留的 checkpoint 数量 / 总大小（GB）上限。

--ckpt.load_enable

从 --ckpt.path 恢复；无有效 checkpoint 时平稳回退到重新训练。

--ckpt.best_metric_key （PPO）

保存最佳 checkpoint 的评估指标键（空值 = 自动检测第一个 pass1；none = 禁用）。

详细语义与 SFT/PPO 示例见 Checkpoint（检查点）保存与恢复。

Logging

  • --logger.logging_steps：每 N 个训练步骤记录一次日志。

  • --logger.wandb.key {token-or-True}：Wandb（实验跟踪平台）日志（True 使用先前的 wandb login）。

  • --logger.wandb.org / --logger.wandb.group / --logger.wandb.project / --logger.wandb.run_name：Wandb 元数据。

  • --logger.tensorboard_dir {logdir}：TensorBoard（训练可视化工具）日志路径。

Model / entity flags

PPO 通过四个平行配置分组组织模型配置：

前缀

作用范围

--actor.*

策略模型（参与训练）。包含优化器 / 调度器 / 梯度裁剪、损失参数（eps_clip、dual_clip、entropy_coef、aux_loss_coef、policy_loss_type、entropy_coef）、gradient_checkpointing_enable、freeze_visual_encoder。

--critic.*

价值网络。包含独立优化器配置分组，以及 value_clip、save_value_network、freezing_steps（critic 预热时冻结 actor；尽管名称如此，它位于 critic 分组下，配合 critic 训练）。

--ref.*

冻结的参考模型。offload 在前向计算之间将其移至 CPU。

--reward.*

奖励模型 / 函数。包含 model_name_or_path、remote_url（HTTP（网络协议）RM 或本地 .py 奖励函数）、normalize_enable、clip_range、overlong_buffer_len / overlong_penalty_factor、stop_properly_penalty_coef、offload。评分头前缀位于 --ds.value_head_prefix 下。

每个 PPO 实体均有自己的 --{entity}.num_nodes / --{entity}.num_gpus_per_node。

引擎级模型加载选项——--ds.attn_implementation、--ds.experts_implementation、--ds.use_liger_kernel、--ds.load_in_4bit、--ds.lora.*、--ds.packing_samples——由所有角色共享，不能为每个实体分别设置注意力实现或 LoRA 配置。

SFT / RM / DPO 使用单模型命名空间 --model.*：

标志

含义

--model.model_name_or_path

HF 模型名称或路径。

--model.gradient_checkpointing_enable / --model.gradient_checkpointing_reentrant

以计算换取显存（重新计算激活值）；reentrant（重入模式）开关。

--model.aux_loss_coef

MoE 负载均衡损失系数（MoE 模型为 > 0）。

--model.beta （DPO）

DPO 温度。

--model.ipo_enable / --model.label_smoothing / --model.nll_loss_coef （DPO）

IPO（隐式偏好优化）开关 / cDPO（保守 DPO）平滑 / NLL（负对数似然）正则化。

--model.loss_type / --model.compute_fp32_loss_enable / --model.margin_loss_enable （RM）

奖励模型损失类型。评分头前缀为 --ds.value_head_prefix。

--model.pretrain_mode_enable （SFT）

预训练形式损失（对整个序列预测下一 token）。

SFT / RM / DPO 的引擎级模型加载（attn_implementation、experts_implementation、use_liger_kernel、load_in_4bit、lora.*、packing_samples）同样位于 --ds.* 下。

Optimizer: Adam or Muon

0.10.2 在 --adam.* 与 --muon.* 下提供两个平行的优化器配置分组，在运行时由单一开关选择：

  • SFT / RM / DPO 中使用 --optim {adam, muon}。

  • PPO 中使用 --actor.optim {adam, muon} 与 --critic.optim {adam, muon}（actor / critic 相互独立，原生支持 actor 使用 Muon、critic 使用 Adam）。

Pure Adam

标志

含义

--adam.lr （SFT/RM/DPO） / --actor.adam.lr / --critic.adam.lr （PPO）

学习率。

--adam.betas

Adam β₁/β₂（默认 (0.9, 0.95)）。

--adam.eps

Adam ε（默认 1e-8）。

--adam.weight_decay

L2 权重衰减（替换旧扁平选项 --l2）。

Muon (--optim muon)

DeepSpeed 的 MuonWithAuxAdam 对二维隐藏层权重矩阵使用 Muon，并为 embedding（嵌入）/LM head（语言模型输出头）/一维参数使用平行的 AdamW（解耦权重衰减优化器）子组。OpenRLHF 0.10.2 直接控制此行为：

标志

含义

--muon.lr

Muon 二维权重组的 LR（学习率）（默认 0.02）。

--muon.momentum

Muon 动量（默认 0.95）。

--muon.ns_steps

Newton–Schulz（矩阵迭代法）迭代次数。占位选项——DeepSpeed 0.18.x 将其硬编码为 ns_steps=5，位于 muon_update() 内；更改此值会触发运行时警告。提供此选项是为兼容未来 DeepSpeed 版本。

--muon.nesterov / --muon.no_nesterov

Nesterov（前瞻动量）开关。占位选项——DeepSpeed 0.18.x 硬编码为启用 Nesterov。

aux-Adam（辅助 Adam）子组（embedding / LM head / 一维参数 / value head（价值输出头））复用 --adam.lr、--adam.betas、--adam.eps、--adam.weight_decay，LR 调度器同时控制两个组。PPO 按实体配置：--actor.muon.lr、--critic.muon.lr 等。

说明

要求与注意事项

  • 需要 DeepSpeed ≥ 0.18.2。

  • 不兼容 --ds.adam_offload，Muon 将状态保存在 GPU。

  • 共享权重衰减。DeepSpeed 0.18.x 为 Muon 与 aux-Adam 参数组写入同一个 weight_decay；因此 OpenRLHF 从 --adam.weight_decay（或 --{entity}.adam.weight_decay）读取并应用于两组。不存在独立 --muon.weight_decay 选项。

  • Muon 不应用 bias（偏置）/LayerNorm（层归一化）的权重衰减豁免。DS Muon 将扁平 Parameter 列表通过 p.use_muon 划分，不接受参数组字典；初始化后拆分组会使 ZeRO 的 bit16/fp32 元数据失去同步。纯 Adam 路径仍照常免除 bias / LayerNorm 的权重衰减。

  • 0.10.2 修复。此前 aux-Adam 子组会静默继承 Muon 的 LR（0.02），导致预训练 embedding 在最初约 100 步被破坏。0.10.2 显式向 DS 传递 muon_lr 与 adam_lr，使各组遵循自己的初始 LR。务必设置 --adam.lr（PPO：--actor.adam.lr），当使用 --optim muon 训练时。
