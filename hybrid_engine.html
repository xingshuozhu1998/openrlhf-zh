Hybrid Engine（混合引擎）

Hybrid Engine 将所有 RL（强化学习）组件——Actor（策略模型）、Critic（价值评估模型）、Reward（奖励模型）、Reference（参考模型）及 vLLM（大模型推理引擎）——共置在同一组 GPU（图形处理器）上，通过显存休眠模式按时间共享。显存允许时推荐此设置：部署最简单，所需 GPU 最少，吞吐量通常最佳。

整体架构见 架构基础：Ray（分布式计算框架）+ vLLM（大模型推理引擎）分布式架构，调优见 性能调优。

How sleep mode works

简单的分布式 RL 设置中，vLLM 在训练期间闲置，DeepSpeed（分布式深度学习优化库）在生成期间闲置，浪费一半 GPU 时间。Hybrid Engine 通过按时间共享同一组 GPU解决：

  1. 生成阶段：vLLM 唤醒并使用大部分 GPU 显存（KV cache（键值缓存）+ 权重）。DeepSpeed 引擎休眠（卸载 / 最小占用）。

  2. 权重同步：trainer（训练器）通过 NCCL（多 GPU 集合通信库）（--vllm.sync_backend nccl）向 vLLM 广播更新后的 actor 权重。

  3. 训练阶段：vLLM 休眠（--vllm.enable_sleep），DeepSpeed 唤醒（--ds.enable_sleep），对 actor / critic / reference / reward 执行前向传播、反向传播与优化器更新。

由于两端均支持休眠，即使模型较大也可共用一组 GPU。全程承担的显存占用，仅是各端需要常驻的部分（模型权重、由 --vllm.gpu_memory_utilization 控制的 KV cache 预算）。

Launch recipe (Qwen3-4B RLVR — math)

这是整套文档使用的默认 RL 示例：Qwen3-4B-Thinking，使用 REINFORCE++-baseline（带基线的策略梯度算法） 在数学推理（RLVR（可验证奖励强化学习））上训练，用 Python 奖励函数验证答案。改编自上游 train_reinforce_baseline_hybrid_engine.sh 与 train_prorlv2_math_hybrid_engine.sh。

# launch the master node of ray in a container
ray start --head --node-ip-address 0.0.0.0 --num-gpus 8

# additional worker nodes (optional)
ray start --address {MASTER-NODE-ADDRESS}:6379 --num-gpus 8

ray job submit --address="http://127.0.0.1:8265" \
   --runtime-env-json='{"working_dir": "/openrlhf"}' \
   -- python3 -m openrlhf.cli.train_ppo_ray \
   --actor.model_name_or_path Qwen/Qwen3-4B-Thinking-2507 \
   --reward.remote_url examples/python/math_reward_func.py \
   --data.prompt_dataset zhuzilin/dapo-math-17k \
   --data.input_key prompt \
   --data.label_key label \
   --data.apply_chat_template \
   --ds.packing_samples \
   \
   --ref.num_nodes 1 \
   --ref.num_gpus_per_node 4 \
   --actor.num_nodes 1 \
   --actor.num_gpus_per_node 4 \
   --vllm.num_engines 2 \
   --vllm.tensor_parallel_size 2 \
   --train.colocate_all \
   --vllm.gpu_memory_utilization 0.7 \
   --vllm.enable_sleep \
   --ds.enable_sleep \
   --vllm.sync_backend nccl \
   --vllm.enforce_eager \
   \
   --algo.advantage.estimator reinforce_baseline \
   --algo.kl.use_loss \
   --algo.kl.estimator k2 \
   --algo.kl.init_coef 1e-5 \
   --actor.entropy_coef 0.0 \
   --algo.advantage.is_correction_enable \
   --algo.advantage.is_correction_type icepop \
   \
   --rollout.batch_size 128 \
   --rollout.n_samples_per_prompt 8 \
   --train.batch_size 1024 \
   --algo.dynamic_filtering_enable \
   --algo.dynamic_filtering_range 0.0 1.0 \
   --train.dynamic_batch_enable \
   --train.max_tokens_per_gpu 16192 \
   --rollout.max_tokens_per_gpu 32768 \
   --train.micro_batch_size 1 \
   --rollout.micro_batch_size 8 \
   --data.max_len 74240 \
   --rollout.max_new_tokens 64000 \
   --data.max_samples 128000 \
   --train.max_epochs 1 \
   --train.num_episodes 1 \
   \
   --ds.zero_stage 3 \
   --ds.param_dtype bf16 \
   --actor.gradient_checkpointing_enable \
   --ds.ring_attn_size 2 \
   --ds.ring_attn_head_stride 2 \
   --actor.adam.lr 5e-7 \
   \
   --ckpt.output_dir ./exp/Qwen3-4B-Thinking \
   --ckpt.path ./exp/Qwen3-4B-Thinking/ckpt \
   --ckpt.save_hf \
   --ckpt.max_num 3 \
   --ckpt.save_steps 10 \
   --logger.logging_steps 1 \
   --eval.steps -1

说明

  • 适用于任意 RL 算法，修改 --algo.advantage.estimator 切换。

  • 适用于单轮与多轮 agent（智能体）模式（参见 RL（强化学习）训练指南）。

  • 要让 actor 使用 Muon（优化器），添加 --actor.optim muon（需 DeepSpeed ≥ 0.18.2，且不再使用 --ds.adam_offload；参见 常用 CLI（命令行接口）选项）。

Key flags

Essential

标志

含义

--train.colocate_all

将 vLLM 引擎、Actor、Reference、Reward 与 Critic 共置在同一组 GPU。

--vllm.gpu_memory_utilization <0..1>

vLLM KV-cache（注意力键值缓存） 比例。8×A100 上从 0.5 开始，稳定后提高。

--vllm.enable_sleep

vLLM 休眠模式，在 rollout（采样生成）之间释放大部分 vLLM 显存。

--ds.enable_sleep

DeepSpeed 休眠模式，在训练步骤间释放 DeepSpeed 显存。

--vllm.sync_backend nccl

用于权重同步的 NCCL 后端（比默认更快）。

--vllm.enforce_eager

禁用 vLLM CUDA（NVIDIA 的并行计算平台） graph（GPU 计算图）（某些设置必需，可减少显存占用）。

Finer-grained colocation (when not using --train.colocate_all)

标志

含义

--train.colocate_critic_reward

将 Critic 与 Reward 放在同一组 GPU。

--train.colocate_actor_ref

将 Actor 与 Reference 放在同一组 GPU。

--ref.offload / --reward.offload

Actor 训练阶段，将 Reference / Reward 卸载至 CPU（中央处理器）。

Memory rule of thumb

vllm.gpu_memory_utilization + 模型显存 < 1.0。8×A100（80GB）示例：

建议 --vllm.gpu_memory_utilization

Relationship to async training

--vllm.enable_sleep 不兼容 --train.async_enable（trainer 会检查此条件；异步模式持续运行 vLLM）。--train.colocate_all 仍可与 --train.async_enable 组合，但异步模式下只把 DeepSpeed 模型共置在共享 GPU；vLLM 保留独立 GPU 组以持续生成。若愿意以 off-policy（异策略）噪声换更高吞吐量，参见 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）。

When not to use Hybrid Engine

以下情况切换到分布式模式（各角色使用独立 GPU 组）：

  • 降低 --vllm.gpu_memory_utilization 并启用全部显存节省措施后，仍发生 OOM（内存不足）。

  • 模型足够大（70B+），没有单个 GPU 能容纳模型与 KV cache。

  • 希望通过异步 + partial rollout（可中断并恢复的部分采样）获得最大吞吐量（参见 RL（强化学习）训练指南）。

完整调优指南见 性能调优；OOM / NCCL / vLLM 挂起问题见 故障排查。
