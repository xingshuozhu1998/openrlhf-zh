设计范式：基于 Agent（智能体）的执行

OpenRLHF（开源强化学习训练框架）是首个通过统一的智能体流水线，将执行模式与 RL（强化学习）算法解耦的 RLHF（基于人类反馈的强化学习）框架。所有训练任务，无论标准 PPO（近端策略优化）、GRPO（组相对策略优化）推理、多轮工具使用、VLM（视觉语言模型）数学任务，还是异步 DAPO（解耦裁剪与动态采样策略优化），都通过同一个 AgentExecutorBase（智能体执行器接口）运行，并产生相同类型的 token（文本词元）级轨迹。RL 损失层以相同方式处理它们。

本页介绍设计理念、其实际意义，以及各组件如何配合。可运行实践方案见 RL（强化学习）训练指南；底层分布式基础设施见 架构基础：Ray（分布式计算框架）+ vLLM（大模型推理引擎）分布式架构。

Why agent-based?

传统 RLHF 流水线将两类问题混在一起：如何采集经验（单轮生成、与环境多步交互、工具调用）与如何更新策略（PPO、GRPO、REINFORCE++（改进策略梯度方法）等）。二者耦合时，每种新执行模式都需要深入修改训练器，每种新算法也必须针对各模式重新实现。

OpenRLHF 的智能体范式将二者分离：

  • Agent executors（智能体执行器）产生token 级轨迹，包含输入 token、输出 token、对数概率、可选的环境图像和逐步奖励。

  • RL 算法通过统一的共享损失计算层使用该轨迹。

由于接口边界采用 token-in / token-out（词元输入/词元输出），rollout（策略采样生成）与训练之间完全没有文本级重新分词或字符串拼接。这类操作是细微 RLHF 错误最常见的来源，例如对话模板漂移、BOS/EOS（序列起始/结束标记）不匹配，以及特殊 token 处理问题。

               ┌─────────────────────────────┐
               │    AgentExecutorBase        │
               │  (Token-in-Token-out Core)  │
               └─────────────────────────────┘
                            │
               ┌────────────┴────────────┐
               ↓                         ↓
       SingleTurnExecutor        MultiTurnExecutor
               │                         │
    ┌──────────┴──────────┐   ┌─────────┴──────────┐
    ↓                     ↓   ↓                    ↓
Standard RLHF      Custom Reward   Multi-Step    External Env
(One-shot gen)     Function (RFT)  Reasoning     (OpenAI Agent Server)
    ↓                     ↓           ↓                ↓
    └─────────────────────┴───────────┴────────────────┘
                            │
                  Consistent Token Trajectories
                            │
                  ┌─────────┴─────────┐
                  │  RL Algorithms    │
                  │  (Decoupled)      │
                  │                   │
                  │  PPO, REINFORCE++ │
                  │  GRPO, RLOO, etc. │
                  └───────────────────┘

用一句话概括数据流：提示词 → 智能体执行器 → token 轨迹与奖励 → 优势计算 → 策略/critic（价值模型）更新。

Core design principles

原则

实际含义

Token-in-Token-out

轨迹保存为 token ID 和对数概率，采样与训练之间从不重新解码为文本。消除文本级不匹配，完整保留 vLLM（大模型推理引擎）产生的结果。

统一接口

单轮与多轮共享同一个 AgentExecutorBase API（应用编程接口）。切换模式只需更改一个标志（--train.agent_func_path），训练器代码路径完全相同。

与算法无关

算法（PPO、REINFORCE++、GRPO、RLOO（留一法奖励基线方法）、Dr. GRPO（修正 GRPO 偏差的变体）、REINFORCE++-baseline（采用奖励基线的 REINFORCE++））通过 --algo.advantage.estimator 选择，使用相同轨迹格式。新增算法无需修改执行器。

与流水线无关

同步（Hybrid Engine（混合引擎））与异步（可选 partial rollout（可中断并恢复的部分采样生成））流水线都接入同一损失层。吞吐量与 on-policy（同策略）程度之间的取舍由部署决定，而非算法决定。

可扩展

自定义奖励（单轮 RFT（强化微调））通过 Python（编程语言）文件路径指定；自定义环境（多轮）是 AgentInstanceBase 的子类。无需修改训练器。

可用于生产环境

内置支持可恢复检查点、最佳检查点跟踪、EMA（指数移动平均）、多节点 SLURM（集群作业调度系统）、Wandb（实验跟踪工具）/TensorBoard（训练可视化工具）、off-policy（异策略）修正、长度惩罚和动态过滤，均作为同一流水线上的模块化标志提供。

Pipelines (sync vs. async)

第三个独立维度，根据吞吐量与收敛之间的取舍选择。

流水线

行为

适用时机

同步（Hybrid Engine）

Rollout → 训练 → rollout（每次执行一个阶段，模型通过休眠模式共享 GPU（图形处理器））

默认选择，收敛最稳定；GPU 同置时吞吐量最佳。见 Hybrid Engine（混合引擎）。

异步

rollout 与训练通过有界队列（--train.async_queue_size）并发运行，样本略带 off-policy 性质

适用于吞吐量至关重要且已验证收敛的场景。--train.async_enable。

异步 + Partial Rollout

生成持续进行；vLLM 在请求尚未完成时通过暂停/恢复切换权重

最大程度重叠；在途样本可能同时包含旧权重与新权重生成的 token。--train.async_enable --train.partial_rollout_enable。见 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）。

Mental model in one sentence

分别选择算法、执行模式和流水线这三项独立配置，OpenRLHF 就会端到端运行同一个训练循环。

How to use

选择执行模式

  • 单轮（默认）：无需额外标志；自定义奖励可使用 --reward.remote_url <http-url-or-py-file>。

  • 多轮：--train.agent_func_path /path/to/agent_func.py。

选择 RL 算法 — 将 --algo.advantage.estimator 设为以下之一：

  • gae — PPO（默认；使用 critic）。

  • reinforce — REINFORCE++。

  • reinforce_baseline — REINFORCE++-baseline（推荐用于 RLVR/推理）。

  • rloo — RLOO。

  • group_norm — GRPO。

  • dr_grpo — Dr. GRPO。

选择流水线

  • 同步 + Hybrid Engine（默认）：--train.colocate_all --vllm.enable_sleep --ds.enable_sleep。

  • 异步：--train.async_enable（可选 --train.async_queue_size N）。

  • 异步 + partial rollout：--train.async_enable --train.partial_rollout_enable。

覆盖每种组合的可运行实践方案见 RL（强化学习）训练指南。

警告

实现自定义多轮智能体时，请始终遵循 token-in-token-out 原则，操作 states["action_text"] 等接口返回的 token ID，而不是手动拼接的文本字符串，否则可能在采样与训练之间引入难以察觉的文本级不匹配。
