性能调优

本指南汇总对吞吐量及显存最重要的配置选项。Hybrid Engine（混合引擎）细节见 Hybrid Engine（混合引擎），错误排查见 故障排查。

经验原则：从已知可用的 recipe（训练方案）（见 examples/scripts）开始，每次只调整一个选项。

选择部署模式

根据优化目标选择：

  • 最高吞吐量 → 异步训练（--train.async_enable）。通过有界队列重叠 rollout（轨迹采样）与训练；用 --train.async_queue_size 调整异步程度（从 1 开始，仅当 rollout 成为训练瓶颈时增大）。添加 --train.partial_rollout_enable，重叠权重同步与生成。见 异步训练与 Partial Rollout（可中断并恢复的部分采样生成）。

  • 最高稳定性 → Hybrid Engine（--train.colocate_all --vllm.enable_sleep --ds.enable_sleep）。完全 on-policy（同策略），在共享 GPU（图形处理器）上切换角色，实现极佳 GPU 利用率。对收敛敏感工作负载而言，是稳妥的默认方案。见 Hybrid Engine（混合引擎）。

  • 分布式模式（vLLM（大模型推理引擎）/ Actor（策略模型）/ Critic（价值模型）使用独立 GPU 组）是无法同置的极大模型或混合硬件集群的备选方案。按各组自身显存和计算需求配置规模。

加速选项

选项

标志

使用时机/原因

Sample packing（样本打包）

--ds.packing_samples

始终开启：移除填充，大幅加速训练。

NCCL（GPU 集合通信库）权重同步

--vllm.sync_backend nccl

多 GPU 时始终开启，比默认方式更快。

动态批次

--train.dynamic_batch_enable + --train.max_tokens_per_gpu / --rollout.max_tokens_per_gpu

序列长度变化时，比固定 micro-batch（微批次）利用率更好。

异步训练

--train.async_enable

最快方案。用 --train.async_queue_size 调节异步程度（从 1 开始）。先在同步模式验证收敛。

Partial rollout（部分采样）

--train.partial_rollout_enable

配合 --train.async_enable，重叠生成与权重同步。搭配 --algo.advantage.is_correction_enable。

Hybrid Engine

--train.colocate_all + --vllm.enable_sleep + --ds.enable_sleep

最稳定的高吞吐量方案。担心 off-policy（异策略）噪声时最佳。

Overlap comm（通信重叠）

--ds.overlap_comm

显存充足时，重叠反向传播和梯度归约。

DeepCompile（DeepSpeed（分布式训练优化框架） 图编译）

--ds.deepcompile

PyTorch（深度学习框架）2.0+，DeepSpeed（分布式训练框架）图编译。

Prefix caching（前缀缓存）

--vllm.enable_prefix_caching

--rollout.n_samples_per_prompt > 1：复用共享 prompt 的 KV（键值缓存）。

显存管理

显存 充足时：

  • 禁用 --ds.adam_offload；启用 --ds.overlap_comm。

  • 使用 --train.colocate_all（Hybrid Engine），或至少 --train.colocate_critic_reward + --train.colocate_actor_ref。

遇到 OOM（内存不足）时（按优先顺序）：

  1. 启用 --ds.packing_samples 和 --actor.gradient_checkpointing_enable。

  2. 减小 --train.micro_batch_size / --rollout.micro_batch_size。

  3. 降低 --vllm.gpu_memory_utilization（如 0.6 → 0.5 → 0.4）。

  4. 启用 --ds.adam_offload；增大 --ds.zero_stage（2 → 3）。

  5. 禁用同置（移除 --train.colocate_*），改用分布式模式。

说明

--ds.adam_offload 不兼容 --actor.optim muon / --critic.optim muon，DeepSpeed 的 Muon（矩阵参数优化器）将优化器状态留在 GPU。若需 adam-offload 节省显存，请用 Adam（优化器）或禁用 Muon。

批次大小调优

  • 生成：尽量增大 --rollout.micro_batch_size，减小 vLLM TP（张量并行）规模（优先更多引擎，而非更大 TP）。

  • 训练：尽量增大 --train.micro_batch_size，同时启用 --ds.packing_samples。

  • 批次关系：常见选择为 train.batch_size = rollout.batch_size * rollout.n_samples_per_prompt。

长上下文（>8K token）

  • 启用 RingAttention（环形注意力）（--ds.ring_attn_size），参见 Sequence Parallelism（序列并行，RingAttention）。

  • 保持 --ds.packing_samples 开启。

  • 增大 --ds.zero_stage（通常为 3），密切监控显存。

启动 recipe（方案）见 Hybrid Engine（混合引擎） 和 RL（强化学习）训练指南；错误排查见 故障排查。
